Base: `ca25fa67`. Parent acceptance task `01a08ff2-8ac8-7b61-9793-036f75bd9b83` owns live writes, merge, deployment, and final acceptance. This follow-up addresses only the five failures reported during that deployment's acceptance batch.

## Changes and evidence

1. **Computed native filters.** Reproduced live on Stock: Product Equals `E2E Shirt` returned no rows although base and variant rows were present. The earlier #448 fix supplied `SortBy`, but flat grids also require `GetSortAndFilterExpression`. BlazorBlueprint 3.16 template columns omit that interface projection and fall back to reflection on a property name. `InventoryTemplateColumn` is a small compatibility subclass of the existing Blueprint column; it exposes `FilterBy` as the projection. Native `BbDataGrid` rendering, pagination, and filter controls remain in use. Filterable Inventario template columns use this subclass; action columns are unchanged. Two regression tests exercise the library's real flat-grid filtering pipeline for both `IEnumerable` and `IQueryable` with computed lookup labels. The actual compiled Stock page, seeded with controlled local data, returns both base and Medium Shirt rows and excludes Water (`stock-computed-filter.*`).

2. **Reservation prerequisites.** The page requested `Take(2000)` for allocations, exceeding the remote executor's 1000-row limit before product prerequisites could load. It now uses the existing `GetReservationAllocations` wrapper, passing `BuildMetadata()` with the active `TenantFilter.SelectedTenantId`. The wrapper retains its own tenant authorization and existing bounded result. No authorization policy or backend endpoint was changed. Failed loads now show a persistent retry state, close/reset the draft, clear all loaded collections, and expose no Reserve action. Successful loads also disable Reserve when products, warehouses, or locations are absent. `reservation-load-error.*` shows the actual Reservations component, including after a failed Retry. The allocation wrapper read passed a real PostgreSQL/Bolt integration test. A diagnostic direct-query test also returned 403 for Product, so that test is not evidence of an allocation-specific authorization defect; the invalid 2000-row request is independently confirmed by executor validation.

3. **Receipt detail.** The actual ReceivingDocumentDetail component now shows `Base product` versus `Size: QA Medium`, stored units (`each` and `kg` in the local fixture), and numeric `2.50` under `Unit cost (SGD)`. Tenant currency and variant labels use existing helpers; missing units say `Not recorded`. Variant lookups retain the existing bounded tenant-query pattern, avoiding unsupported local collection predicates. See `receipt-detail.*`.

4. **Topmost Escape.** Reproduced live: Escape from the Warehouse picker closed the whole receiving dialog. Blueprint 3.16 uses separate document listeners for dialog Escape and popover Escape. The Inventario helper intercepts this case only when an expanded entity picker is inside `.inv-dialog`; it invokes the popover's existing outside-dismiss path with a pointer pair targeted inside the parent dialog, preventing the parent Escape listener from seeing the same key. The actual Receiving component retained `LOCAL-ESCAPE-DRAFT`, closed the picker, and focused Warehouse after the first Escape. A later Escape closed the dialog normally and focused Receive Stock (`escape-first.txt`, `escape-second.txt`). Shared picker source and POS behavior are unchanged; the handler is scoped to Inventario dialogs.

5. **Mobile selected dates.** Reproduced the actual Receiving component's fixed 280-pixel date buttons overflowing a 246-pixel inner field. Dialog buttons now respect their containing width; no horizontal overflow is hidden. With manufacture `9/11/2026` and expiry `9/18/2026` selected at 390×844, each date button is 246 pixels, and the dialog body's client and scroll widths are both 298 pixels. The selected date controls and footer remain visible (`receiving-selected-dates-390.png`). Existing entity-picker text truncation is intentional and does not overflow the dialog.

The host now uses the built-in fingerprinted asset references for the changed CSS and Inventario JavaScript. A cached prior script was detected during verification; fingerprints ensure an updated deployment receives these fixes.
