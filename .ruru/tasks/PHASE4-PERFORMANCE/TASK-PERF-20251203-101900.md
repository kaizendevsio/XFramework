# Phase 4: Performance Optimization - EF Core Query Optimizations

## Objective
Apply EF Core performance optimizations across all service files to reduce memory allocations and improve query performance.

## Background
Phase 3 VSA migration is complete. Now we need to optimize database queries with:
1. `AsNoTracking()` for read-only queries (reduces memory and improves performance)
2. `AsSplitQuery()` for queries with multiple Includes (prevents cartesian explosion)

## Implementation Pattern

**Before:**
```csharp
var wallet = await _dbContext.Set<Wallet>()
    .Where(w => w.TenantId == tenant.Id && w.Id == walletId)
    .FirstOrDefaultAsync(cancellationToken);
```

**After:**
```csharp
var wallet = await _dbContext.Set<Wallet>()
    .AsNoTracking()
    .Where(w => w.TenantId == tenant.Id && w.Id == walletId)
    .FirstOrDefaultAsync(cancellationToken);
```

**For queries with Include:**
```csharp
var product = await _dbContext.Set<Product>()
    .AsNoTracking()
    .AsSplitQuery()
    .Include(p => p.Category)
    .FirstOrDefaultAsync(p => p.Id == id && !p.IsDeleted, ct);
```

## Success Criteria
- All read-only queries have AsNoTracking()
- All queries with multiple Includes have AsSplitQuery()
- Solution builds with 0 errors
- All tests pass

## Notes
- DO NOT add AsNoTracking to queries where the entity is subsequently modified
- AsNoTracking should be placed early in the query chain for clarity
- AsSplitQuery helps prevent cartesian product explosion with multiple joins
