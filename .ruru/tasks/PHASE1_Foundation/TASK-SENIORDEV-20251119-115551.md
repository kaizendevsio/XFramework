## Description

- We're building foundation infrastructure before migrating modules
- Phase 1.1 (Project Structure) and 1.2 (Result Pattern) are complete

- Implement graceful fallback if Redis unavailable

## Technical Notes

**Serialization:**
- Use `System.Text.Json` for serialization (not Newtonsoft.Json)
- Configure for proper handling of derived types if needed

**Cache Expiration Strategy:**
- Sliding expiration for frequently accessed data
- Absolute expiration for time-sensitive data
- Make expiration configurable per cache operation

**Redis Considerations:**
- Use connection multiplexing (single IConnectionMultiplexer)
- Implement retry logic for transient failures
- Consider using pub/sub for cache invalidation across instances (future enhancement)

**Result Pattern Usage:**
```csharp
public async Task<Result<T?>> GetAsync<T>(string key, CancellationToken ct = default)
{
    try
    {
        // Try L1 (Memory) first
        if (_memoryCache.TryGetValue(key, out T? cached))
            return Result<T?>.Success(cached);
        
        // Try L2 (Redis)
        var redisValue = await _distributedCache.GetStringAsync(key, ct);
        // ... deserialize and cache in L1
        
        return Result<T?>.Success(value);
    }
    catch (Exception ex)
    {
        return Result<T?>.Failure($"Cache retrieval failed: {ex.Message}", 500);
    }
}
```
